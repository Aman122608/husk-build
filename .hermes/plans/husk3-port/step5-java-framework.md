# Step 5 — `src/java-framework/` ported into husk3.0

**Target:** `C:/Users/Aiden/Desktop/husk3.0`, branch `husk3`, commit **`4059586`** (pushed to
`origin` = `Aman122608/husk-build`; `git ls-remote origin husk3` returns that same SHA).
**Source:** `C:/Users/Aiden/Desktop/HuskApp` (our fork, "Husk 2.0").

This is the port that makes the dex this repo builds contain its own Java framework. The IPA was
being rejected by `tools/check-shipped-dex.py` with `MISSING resetForNewApp` / `MISSING AdSurfaces`
because `src/java-framework` was never carried across. It is now.

---

## The measurement that changed the shape of the job

Before touching anything, the two trees were compared file by file and each differing file was
diffed against **upstream HEAD** (`https://raw.githubusercontent.com/Leviidev/Husk/main/...`).

The two findings that the brief got wrong (it had already been wrong five times):

1. **The target's `src/java-framework` is byte-identical to upstream HEAD** for all 37 differing
   files. So the target was a clean upstream snapshot, not a half-ported tree: the missing symbols
   were ours, not deleted upstream work.
2. **Upstream is *newer* in this directory, not older.** Its `Instrumentation.java`, `LoadedApk.java`
   and `NetworkSecurityPolicy.java` are hand-written classes under `src/android/...`; our fork has
   only *older generated stubs* of the same three classes under `gen-src/android/...`. Its
   `AppRunner.java` carries loader-swap adoption, `appComponentFactory` support,
   `ActivityThread.huskBind` and `Documents` handling that our fork never had — while our fork brings
   the shutdown/reset machinery upstream never had.

So **every differing file is a two-way merge**, and the job was "keep upstream's newer lines, add
ours", per file — never a copy. Each file's direction was established by diffing, and the symbols
our additions call were checked to exist in the target (`grep`), not assumed.

**Only one file was genuinely ours-only.** The brief listed four to port, but three of its four —
`gen-src/android/app/{Instrumentation,LoadedApk}.java` and
`gen-src/android/security/NetworkSecurityPolicy.java` — **must not be ported**:

- Upstream already ships newer hand-written `src/android/app/Instrumentation.java`,
  `src/android/app/LoadedApk.java`, `src/android/security/NetworkSecurityPolicy.java`.
- Our copies are stale generated stubs (`// Generated by tools/compat/genstubs.py`). `LoadedApk` in
  ours is a 254-byte empty abstract class against upstream's 3,785-byte packer record;
  `NetworkSecurityPolicy` in ours defaults `isCleartextTrafficPermitted()` to **false** (deny)
  against upstream's always-permit.
- Both trees compile **both** `src/` and `gen-src/` (`build.sh` line 12:
  `find "$HERE/src" "$HERE/gen-src" -name '*.java'`). Copying ours into `gen-src/` beside upstream's
  `src/` copy is a **duplicate class → javac error**, i.e. the exact "Build Husk's Java framework"
  step the check tells you to fix. `gen/stubs.txt` is likewise left unchanged (ours added
  `android.app.Instrumentation` and `android.security.NetworkSecurityPolicy` lines that would
  regenerate those stubs and collide).

  `husk.AdSurfaces.refuse(String)`, and the real `android.os.Process.killProcessQuiet/sendSignal/

  `.class` output that d8 will carry into `husk-framework.dex`.
- Judgement calls, flagged rather than hidden: (a) `InputDevice`'s two strings (reasoning above);
  (b) the ~20 "unchanged" files — each was diffed and read, and the decision was "upstream is newer",
  but a behavioural claim (e.g. `View.getDrawingCache` caching, `TextView.applyCompoundDrawables`) is
  upstream's and was not exercised on a device.
- The CI step **"Build Husk's Java framework (from this repo)"** plus **`check-shipped-dex.py`** are
  where this is finally judged; the local `javac` above is the closest this machine allows.
